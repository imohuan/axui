# 05 - 构建与发布流程

## 构建架构

shadcn-vue 的构建分为两个独立的子系统：

1. **CLI 包的构建** (packages/cli) - 发布为 npm 包
2. **文档网站 + Registry 的构建** (apps/v4) - 部署到 Cloudflare

## 一、CLI 包的构建

### 构建工具

使用 `tsdown` 作为打包工具：

```json
{
  "scripts": {
    "dev": "tsdown --watch",
    "build": "tsdown"
  }
}
```

### 构建产物

```
packages/cli/dist/
├── index.js         # CLI 入口 (bin)
├── index.d.ts       # 类型声明
├── registry/        # Registry 相关
│   ├── index.js
│   └── index.d.ts
├── schema/          # Schema
│   ├── index.js
│   └── index.d.ts
├── mcp/             # MCP 服务器
│   ├── index.js
│   └── index.d.ts
├── utils/           # 工具函数
│   ├── index.js
│   └── index.d.ts
├── icons/           # 图标
│   ├── index.js
│   └── index.d.ts
├── preset/          # 预设
│   ├── index.js
│   └── index.d.ts
└── tailwind.css     # 基础 CSS
```

### 发布流程

```
1. pnpm build              # 构建 CLI
2. pnpm pub:beta           # 发布 beta 版本
   或 pnpm pub:release     # 发布正式版本
```

```json
"pub:beta": "pnpm build && pnpm publish --no-git-checks --access public --tag beta",
"pub:release": "pnpm build && pnpm publish --no-git-checks --access public"
```

### CLI 包的 exports 映射

```json
{
  "exports": {
    ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" },
    "./registry": { ... },
    "./schema": { ... },
    "./mcp": { ... },
    "./utils": { ... },
    "./icons": { ... },
    "./preset": { ... },
    "./tailwind.css": { "style": "./dist/tailwind.css" }
  }
}
```

这意味着用户项目可以：
- `import { cn } from "shadcn-vue/utils"` - 访问工具函数
- `import { registryItemSchema } from "shadcn-vue/schema"` - 使用 Zod schema
- `@import "shadcn-vue/tailwind.css"` - 导入基础 CSS

## 二、Registry 的构建

Registry 构建在 apps/v4 中进行，是整个系统的数据源。

### 构建入口

```bash
pnpm registry:build
```

实际执行：

```json
"registry:build": "tsx --tsconfig ./tsconfig.json ./scripts/build-registry.ts && pnpm registry:build:index"
```

### 构建流程

```
Step 1: build-registry.ts
├── 读取 registry.config.ts (构建配置)
├── 对每个 base (如 reka):
│   ├── 对每个 content type (ui, blocks, charts, examples, ...):
│   │   ├── crawlContent(sourcePath)
│   │   │   ├── 读取目录中的 .vue 文件
│   │   │   ├── 解析组件的 props, emits, slots
│   │   │   ├── 提取依赖信息
│   │   │   └── 生成 registry 条目
│   │   ├── 写入到 registry/{outputFile}
│   │   └── 运行 eslint --fix
│   └── 生成 base 的 registry.ts
├── 构建图标注册表
├── 构建 style CSS
└── 运行 formatters (prettier + eslint)

Step 2: build-registries-index.ts
├── 读取所有生成的 registry 文件
├── 生成 __registry__/index.ts (全局索引)
└── 生成 public/r/ 下的 JSON 文件 (供 CLI HTTP 访问)
```

### Registry 构建配置

```typescript
// apps/v4/scripts/registry.config.ts
export const registryConfig = {
  bases: [{
    name: "reka",
    path: "bases/reka",
    contentTypes: [
      { name: "ui", path: "ui", crawlType: "ui", outputFile: "ui/_registry.ts" },
      { name: "blocks", path: "blocks", crawlType: "block", outputFile: "blocks/_registry.ts" },
      { name: "charts", path: "charts", crawlType: "chart", outputFile: "charts/_registry.ts" },
      { name: "examples", path: "examples", crawlType: "example", outputFile: "examples/_registry.ts" },
      { name: "lib", path: "lib", crawlType: "lib", outputFile: "lib/_registry.ts" },
    ]
  }]
}
```

### 构建产出的 JSON 文件

构建后在 `apps/v4/public/r/` 下生成的 JSON 文件是 CLI 通过 HTTP 访问的 registry 数据：

```
public/r/
├── index.json               # 全局索引
├── styles/index.json        # 风格列表
├── icons/index.json         # 图标库列表
├── new-york-v4/index.json   # 组件注册表
└── new-york-v4/             # 每个组件的详细 JSON
    ├── button.json
    ├── dialog.json
    └── ...
```

## 三、文档网站 (apps/v4) 的构建和部署

### 构建

```bash
pnpm build  # 即 pnpm --filter v4 build
```

实际执行 Nuxt 构建：

```json
"build": "NODE_OPTIONS=--max-old-space-size=16384 nuxt build"
```

### 部署流程

```bash
pnpm deploy
```

```json
"deploy": "pnpm build && npx tsx ./scripts/seed-d1.ts && npx wrangler --cwd .output/ deploy && npx tsx ./scripts/purge-cache.ts"
```

部署步骤：
1. 构建 Nuxt 应用
2. 种子数据到 Cloudflare D1 数据库
3. 用 Wrangler 部署到 Cloudflare
4. 清除缓存

### 文档网站的核心功能

文档网站不仅仅展示文档，它还是一个 **Design System Picker**（设计系统配置器）：

1. **配置面板**: 用户可以在网页上选择 Base/Style/Theme/Font/Radius 等所有配置
2. **实时预览**: 组件在不同配置下的实时渲染效果
3. **生成 init 命令**: 根据用户的选择，生成 `npx shadcn-vue init` 命令
4. **iframe 通信**: 通过 composables/useIframeMessageListener.ts 实现与外部 iframe 的消息通信

### 文档网站的特殊技术架构

```
apps/v4 使用 Nuxt 4 + Nuxt Content:
├── content/docs/          # Markdown 文档
├── components/content/    # 自定义渲染组件
├── components/demo/       # 交互式 Demo
├── composables/           # 设计系统状态管理
├── registry/              # 组件注册表 (也是数据源)
└── server/api/            # API 端点
```

## 四、发布流程总结

```
完整发布流程:

1. 修改 registry 中的组件或样式
2. pnpm registry:build           # 重建注册表
3. pnpm lint:fix                 # 代码格式化
4. pnpm test                     # 运行测试
5. pnpm build:cli                # 构建 CLI
6. pnpm pub:release              # 发布 CLI npm 包
7. pnpm deploy                   # 部署文档网站
```

## 五、版本管理

- 使用 `bumpp` 进行版本号管理
- CLI 包版本号和文档网站版本号保持同步
- beta 版本通过 `--tag beta` 发布
- commitlint + simple-git-hooks 确保提交规范
