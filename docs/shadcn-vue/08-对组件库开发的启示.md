# 08 - 对组件库开发的启示

## shadcn-vue 设计哲学的精华

### 1. "Copy-Paste" > "npm install"

**传统组件库**: 安装 npm 包 → import 组件 → 通过 props 定制 → 样式通过 CSS 变量覆盖

**shadcn-vue**: CLI 下载源码 → 组件在项目中 → 直接修改源码 → 完全自由定制

**启示**: 考虑是否可以让组件库支持"源码交付"模式，让高级用户在需要深度定制时不受 API 限制。

### 2. 分层设计

```
Base (底层原语) → Style (视觉风格) → Theme (颜色主题)
```

这三个维度独立变化，互不耦合。

**启示**: 设计组件库时，将以下关注点分离：
- **行为层** (交互逻辑、可访问性) → 对应 Base
- **布局层** (padding、margin、圆角、间距) → 对应 Style
- **色彩层** (颜色、亮暗模式) → 对应 Theme

### 3. CSS 变量驱动的主题系统

不是每个组件定义颜色，而是定义语义化 CSS 变量：

```css
/* 组件中 */
.my-button { background: var(--primary); color: var(--primary-foreground); }

/* 主题中 */
:root { --primary: oklch(0.205 0 0); --primary-foreground: oklch(0.985 0 0); }
.dark { --primary: oklch(0.922 0 0); --primary-foreground: oklch(0.205 0 0); }
```

**启示**: 
- 定义 20-30 个语义化 CSS 变量
- 每个主题只需切换这些变量值
- 支持亮色/暗色双模式
- 使用 OKLCH 颜色空间

推荐的 CSS 变量列表 (参考 shadcn-vue)：

```
background, foreground
card, card-foreground
popover, popover-foreground
primary, primary-foreground
secondary, secondary-foreground
muted, muted-foreground
accent, accent-foreground
destructive, destructive-foreground
border, input, ring
radius
sidebar, sidebar-foreground, sidebar-primary, sidebar-primary-foreground,
sidebar-accent, sidebar-accent-foreground, sidebar-border, sidebar-ring
chart-1, chart-2, chart-3, chart-4, chart-5
```

### 4. 组件 = 无样式原语 + 样式封装

```
Reka UI (无样式) → shadcn-vue 组件 (有样式)
```

**启示**: 不要从零实现所有交互逻辑。可以考虑：
- 使用现有的无样式 UI 库作为基础 (如 Reka UI for Vue, Radix UI for React)
- 或者自己实现一套无样式原语，再封装样式

### 5. CLI 作为分发渠道

不是让用户从 npm 安装组件，而是通过 CLI 下载源码。

**启示**: 开发 CLI 工具处理以下工作：
- 项目初始化 (生成配置、安装依赖)
- 组件添加 (下载源码、解析依赖)
- 版本同步 (diff 命令比较差异)
- AI 集成 (MCP 服务器)

### 6. 注册表 (Registry) 模式

```
Registry API ← CLI 工具 ← 用户项目
```

组件不打包在 npm 中，而是通过 HTTP API 动态获取。

**启示**: 
- 维护一个中心化的组件注册表
- 组件以源代码形式存储
- 支持多版本、多风格
- 提供 JSON API 供 CLI 消费

## 实际开发建议

### 第一步: 确定架构

```
你的组件库架构建议:
├── packages/
│   ├── cli/           # 命令行工具
│   ├── core/          # 核心组件 (可选的 npm 包模式)
│   └── registry/      # 组件注册表定义
├── apps/
│   └── docs/          # 文档网站
├── templates/         # 项目模板
└── docs/              # 内部文档
```

### 第二步: 确定技术栈

参考 shadcn-vue 的选择：

| 层级 | 推荐 |
|------|------|
| 前端框架 | Vue 3 / React 18 |
| 无样式原语 | Reka UI (Vue) / Radix UI (React) |
| CSS 框架 | Tailwind CSS v4 |
| 变体管理 | class-variance-authority |
| 类名工具 | tailwind-merge + clsx |
| CLI 框架 | Commander.js |
| 配置验证 | Zod |
| CLI UI | prompts + ora + consola |
| 构建工具 | tsdown / tsup |
| 测试 | Vitest |
| 文档 | Nuxt Content / Nextra |

### 第三步: 设计 CSS 变量体系

至少定义以下语义化 CSS 变量：

```
颜色 (每个都需要 light/dark 两套):
- background, foreground
- card, card-foreground
- primary, primary-foreground
- secondary, secondary-foreground
- muted, muted-foreground
- accent, accent-foreground
- destructive, destructive-foreground
- border, input, ring

布局:
- radius
- spacing (可选)

组件特化:
- sidebar-*
- chart-1 ~ chart-5
```

### 第四步: 设计组件结构

每个组件遵循统一模式：

```
组件名/
├── ComponentName.vue       # 主组件
├── ComponentNameXxx.vue    # 子组件
├── index.ts                # 导出 + cva 变体
└── (可选) ComponentName.test.ts
```

### 第五步: 设计 CLI 命令

最小可行 CLI：

```
your-lib init       # 初始化项目
your-lib add        # 添加组件
your-lib list       # 列出可用组件
your-lib diff       # 比较版本差异
```

### 第六步: 设计 Registry API

```
GET /api/registry/index.json          # 组件索引
GET /api/registry/{component}.json    # 组件详情和文件
GET /api/registry/themes.json         # 可用主题
GET /api/registry/styles.json         # 可用风格
```

## shadcn-vue 的一些值得借鉴的细节

### 1. data-slot 属性

每个组件都有 `data-slot="component-name"` 属性，对于 CSS 选择器非常有用：

```vue
<template>
  <div data-slot="card" :class="cn('bg-card ...', props.class)">
    <slot />
  </div>
</template>
```

### 2. cn() 函数作为标准模式

每个组件都使用 `cn()` 合并默认样式和用户传入的 class。

### 3. cva 变体暴露

Button 的 `buttonVariants` 和 `ButtonVariants` 类型都导出，让其他组件可以复用：

```typescript
// 在其他组件中
import { buttonVariants } from "@/components/ui/button"

<Link :class="buttonVariants({ variant: 'ghost' })">
  Edit
</Link>
```

### 4. 使用 Primitive 而非原生元素

Button 不是 `<button>`，而是 `<Primitive as="button">`，支持：
- `as="a"` 渲染为链接
- `asChild` 组合模式

### 5. 自动化构建流水线

Registry 的构建是全自动的：爬取组件源码 → 提取类型信息 → 生成注册表 → 格式化代码 → 生成 JSON API。

### 6. 设计系统在线配置器

文档网站不只是一个展示页面，而是让用户**在线配置**设计系统参数，实时预览并生成 init 命令。

## 总结：做组件库的核心思路

1. **组件不是 npm 包，是源码。** 让用户拥有代码，而不是依赖你的包。
2. **分层设计，正交变化。** 行为、布局、颜色各自独立。
3. **CSS 变量是主题系统的核心。** 不是"组件库支持主题"，而是"主题是组件库的基础设施"。
4. **CLI 是分发渠道。** 降低使用门槛，自动化配置。
5. **Registry 是数据源。** 组件以源码形式存在于 registry，CLI 从 registry 获取。
6. **文档网站是设计系统配置器。** 不只是静态文档，而是交互式的配置工具。
7. **底层依赖无样式原语库。** 不重复造轮子，专注于样式和体验。
